# NINJA PANEL — Railway Pterodactyl template

This template adds the **Pterodactyl web panel** image to the repository using the upstream panel image, with a first-admin bootstrap helper. It does **not** deploy Wings into Railway and does not make Railway a Docker host.

## Deployment architecture

- Railway: NINJA PANEL app and optionally the Pterodactyl web panel.
- MariaDB: database service with persistent storage and private networking.
- Redis: cache/queue service, configured using the variables expected by the official Panel image.
- Wings: separate supported Linux VPS/node with Docker, public reachability for allocated ports, and the Wings configuration generated by the Pterodactyl admin panel.

Railway service containers are not a substitute for a supported Linux Docker host. Do not assume Wings can manage the host Docker daemon inside a Railway service. Install Wings on a compatible Linux machine where you control Docker and networking.

## Build and service setup

1. In Railway, create the Panel, MariaDB, and Redis services; attach persistent volumes to database services.
2. Set the Panel service's Dockerfile path to `railway/pterodactyl/Dockerfile`, with repository root as the build context.
3. Set the official Panel image's required environment variables for app URL, database host/port/name/user/password, Redis host/port/password, mail settings and application encryption key. Follow the documentation for the exact upstream image version; do not guess variable values.
4. To create the initial administrator on a fresh database, add:
   - `PTERODACTYL_ADMIN_EMAIL` — administrator email
   - `PTERODACTYL_ADMIN_PASSWORD` — unique, strong password
   - `PTERODACTYL_ADMIN_USERNAME` — optional, defaults to `admin`
   - `PTERODACTYL_ADMIN_FIRST_NAME` / `PTERODACTYL_ADMIN_LAST_NAME` — optional
5. Keep all credentials in private Railway environment variables. Never commit them to GitHub or expose them in frontend JavaScript.
6. Inspect deployment logs, verify migrations and admin login, and test persistent storage. These files have not been deployed or end-to-end tested.

## Linking NINJA PANEL to the Pterodactyl API

Create an Application API key in the Pterodactyl administrator UI with minimum required permissions. Store it only in the NINJA PANEL server's environment, for example `PTERODACTYL_URL` and `PTERODACTYL_APPLICATION_KEY`. The server-side proxy must verify the signed-in NINJA user before using the key; never send the master key to the browser.

## Python and Node.js runtimes

Configure suitable Pterodactyl Eggs/Docker images in the installation. Allocate resources and ports on the Wings node. An API key alone cannot run bots unless a usable Wings node, Egg, allocations and resources are configured.

## Important limitations

- These files add deployment scaffolding for the Pterodactyl web panel, not a finished NINJA-to-Pterodactyl API proxy.
- Wings must be installed on a supported Linux host with Docker access. As there is currently no VPS in the setup, actual bot execution is not yet available.
- Check current Railway plan cost, volume behavior, outbound connections, custom-domain and port support before production use.
